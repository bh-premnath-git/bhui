## DataOps Dashboard Implementation

This document outlines the current implementation of the DataOps Dashboard feature in the `bh-ui` codebase.

### 1. Overview

The DataOps Dashboard provides a user interface to visualize various DataOps metrics through a series of charts. It's designed to fetch dashboard configurations and widget data from an API, though currently, the chart rendering part relies on mock data.

### 2. Key Components and Files

*   **`src/features/dataops/DataOpsHub.tsx`**: 
    *   Main feature component responsible for orchestrating data fetching.
    *   Uses `useDataOpsDashboards` to fetch dashboard lists and `useDataOpsWidgets` to fetch data for individual widgets based on the dashboard layout.
    *   Currently logs fetched API data to the console but does not pass it to the rendering layer.
*   **`src/features/dataops/dataOpsHubs/hooks/useDataOpsDash.ts`**: 
    *   Contains `useDataOpsDashboards` and `useDataOpsWidgets` custom hooks.
    *   `useDataOpsDashboards`: Fetches a list of dashboards (API: `dashboard/list/?dashboard_type=dataops`) or a single dashboard (`dashboard/{id}/`).
    *   `useDataOpsWidgets`: Fetches single widget data (`widgets/{id}/`) or multiple widgets using `useQueries` from `@tanstack/react-query` by their IDs.
    *   Both hooks utilize a generic `useResource` hook and `apiService` for API interactions.
*   **`src/types/dataops/dataops-dash.ts`**: 
    *   Defines TypeScript types for API responses, including `Dashboard`, `Widget`, and `DashboardLayout`.
*   **`src/context/dataops/DataOpsContext.tsx`**: 
    *   `DataOpsProvider` manages the state for the dashboard UI, including filter states, chart order, and the data fed to the charts.
    *   **Crucially, it currently uses mock data generated by `generateData()` and processed by `processChartData()` (from `lib/utils.ts`).**
*   **`src/features/dataops/dashboard/index.tsx` (`DashboardContent`)**: 
    *   Renders the actual dashboard UI, including filters and charts.
    *   Consumes chart data, order, and filter states from `DataOpsContext`.
    *   Implements drag-and-drop for chart reordering using `@dnd-kit`.
*   **`src/lib/utils.ts`**: 
    *   Contains `generateData()`: Creates an array of mock `DataItem` objects.
    *   Contains `processChartData()`: Transforms the mock data into a `ChartData` object suitable for rendering various charts.
*   **`src/types/dataops/data-ops-hub.d.ts`**: 
    *   Defines TypeScript types (`DataItem`, `ChartData`) for the mock data pipeline used by `DataOpsContext` and `lib/utils.ts`.
*   **`src/pages/dataops/DataopsHub.tsx`**: 
    *   The page-level component that renders `features/dataops/DataOpsHub.tsx`.
*   **`src/routes/dataOpsRoutes.tsx`**: 
    *   Defines the client-side routing for the DataOps section, mapping a route (e.g., `/dataops`) to the `DataopsHub` page component.

### 3. Data Flow

There are two distinct data flows currently present:

**A. API Data Fetching (Real Data - Not Visually Rendered in Charts):**

1.  **`DataOpsHub.tsx` Mounts**: The component initiates data fetching.
2.  **Fetch Dashboards**: `useDataOpsDashboards` hook is called to fetch dashboards from `dashboard/list/?dashboard_type=dataops`.
3.  **Extract Widget IDs**: Upon receiving dashboard data, `DataOpsHub.tsx` extracts `widget_id`s from the `dashboard_layout` of the first dashboard.
4.  **Fetch Widgets**: `useDataOpsWidgets` hook is called with the extracted `widget_id`s. This makes individual API calls to `widgets/{id}/` for each widget.
5.  **Data Available**: The fetched `dashboards` and `widgets` data (typed by `dataops-dash.ts`) are available within `DataOpsHub.tsx` and are currently logged to the console.

**B. Chart Data Rendering (Mock Data - Currently Visualized):**

1.  **`DataOpsProvider` Initialization**: When `DataOpsHub.tsx` renders, it wraps its content (which includes the `Dashboard` component) with `DataOpsProvider`.
2.  **Generate Mock Data**: `DataOpsProvider` (from `DataOpsContext.tsx`) calls `generateData()` (from `lib/utils.ts`) to create a set of mock `DataItem`s.
3.  **Process Mock Data**: This raw mock data is then processed by `processChartData()` (from `lib/utils.ts`) to structure it into the `ChartData` format expected by the various chart components.
4.  **Context Value**: The processed `chartData`, along with filter states and chart order, is provided via `DataOpsContext`.
5.  **Render Charts**: `DashboardContent` (from `features/dataops/dashboard/index.tsx`) consumes this mock `chartData` from the context and renders the corresponding charts (e.g., `LatencyTrendChart`, `CostTrendChart`).

### 4. UI Features

*   **Dynamic Chart Rendering**: Displays various types of charts based on (mock) data.
*   **Drag-and-Drop Reordering**: Users can reorder charts on the dashboard, with the order persisted in `DataOpsContext`.
*   **Filtering**: UI for filtering the displayed chart data (operates on the mock data).
*   **Responsive Chart Heights**: Chart heights are dynamically adjusted based on container size using `ResizeObserver`.
*   **Custom Chart Addition**: Includes functionality to add custom charts, potentially triggered by events from other components like `GenericChatUI` (listens for `CHART_ADDED_EVENT`).

### 5. State Management

*   **API Data Fetching & Caching**: Primarily handled by `@tanstack/react-query` (used within `useResource` and `useDataOpsDash.ts`).
*   **UI State (Filters, Chart Order, Mock Chart Data)**: Managed by React Context (`DataOpsContext`). Filter states can be persisted to cookies.
*   **Redux (`dataOpsHubSlice`)**: Appears to be used for managing a list or selection of "DataOps Hubs" as entities, rather than the content of the dashboards themselves. It is not directly involved in the dashboard data rendering flow described above.

### 6. Key Observations & Potential Next Steps

*   **Data Disconnect**: The most significant observation is that the real dashboard and widget data fetched from the API in `DataOpsHub.tsx` is not currently used to render the charts. The charts are driven by a separate mock data generation system within `DataOpsContext.tsx` and `lib/utils.ts`.
*   **Future Integration**: A likely future step would be to integrate the API-fetched data into the `DataOpsContext`. This would involve:
    *   Passing the `dashboards` and `widgets` data from `DataOpsHub.tsx` to `DataOpsProvider`.
    *   Modifying `DataOpsContext` to use this real data instead of `generateData()`.
    *   Potentially adapting or replacing `processChartData()` to transform the API response structure (from `dataops-dash.ts`) into the `ChartData` format expected by the chart components (defined in `data-ops-hub.d.ts`), or updating chart components to accept the API data structure directly.
    *   Ensuring widget configurations (like `chart_config` from the `Widget` type) are used to determine how each widget is rendered.
